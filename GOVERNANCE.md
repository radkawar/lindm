# Governance

The repository owner, [@radkawar](https://github.com/radkawar), makes project-scope, maintainer and release decisions.
This is an early project. There is no foundation or elected steering committee.

Use issues for bugs and proposed changes. Read [CONTRIBUTING](CONTRIBUTING.md) before you open a pull request.
A maintainer reviews changes before they merge. Changes to public APIs, migrations and security boundaries need the design and security review described in [AGENTS.md](AGENTS.md).
Contributors retain their copyright and certify their contributions with the DCO.
The project keeps its git history.

Report vulnerabilities through [private disclosure](SECURITY.md), not a public issue or a `security` label.
The [code of conduct](CODE_OF_CONDUCT.md) applies to all project spaces.

The [roadmap](ROADMAP.md) records planned work, not a release promise.
A release needs the applicable maintainer verification and native qualification evidence.
Public CI does not replace the lab ledger.
Operators build and sign their own v0.1 releases. The project has no official v0.1 signing key.
